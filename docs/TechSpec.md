# ТЗ Сервиса просмотра и конвертации валютных курсов

## Постановка задачи

Необходимо реализовать JSON API сервис для работы с курсами обмена валют (относительно USD).

### Описание

Требуется единый защищенный API для получения актуальных курсов валют и расчета
конвертации между поддерживаемыми валютами. Курсы поступают из внешних провайдеров.

Сервис предоставляет два сценария:

- просмотр списка доступных курсов с необязательной фильтрацией по валютам;
- расчет суммы конвертации с учетом комиссии (2%).

### Цель

Предоставить защищенный, стабильный и документированный API, который позволяет клиенту получать актуальные курсы и рассчитывать
конвертацию.

### Задача

Необходимо реализовать API со следующими возможностями:

- аутентификация запросов по `Authorization: Bearer <token>`,
- получение курсов валют через `GET /api/v1?method=rates`,
- конвертация валют через `POST /api/v1?method=convert`,
- единый JSON формат ответов,
- обработка недоступности внешних источников курсов,
- Легкая поддержка других провайдеров, подключение нового провайдера не должно
  требовать изменения бизнес логики сервисов.

## Решение

В качестве каркаса взят Yii2, предоставляющий контроллеры, классы response и requset, urlmanager, http client,
di контейнер, валидацию, эксепшены и логирование. Эндпоинты реализованы в виде RPC.

### Границы ответственности

API не должен зависеть от формата конкретного внешнего поставщика. Внутри сервиса используются нормализованные курсы
относительно USD, а поставщики отвечают только за получение и преобразование внешних данных.

схема:

```text
Client
  → Nginx
  → API application
      → Authentication / validation
      → RatesService / ConversionService
      → Rate provider
      → External rate APIs
```

### Источники курсов

- Основной источник: https://api.coingate.com/api/v2/rates
- Резервный источник: https://api.coincap.io/v2/rates
- При недоступности основного источника сервис пытается использовать резервный,
  если резеврный недоступен - последний актуальный зашешированный курс.
- Внешние ответы приводятся к единому внутреннему формату курса.

### Бизнес-правила

- Базовая валюта для внутреннего расчета - USD,
- Для каждой валюты необходимо однозначно зафиксировать направление котировки: 1 единица валюты = N USD
- Комиссия сервиса составляет 2%. Комиссия применяется к результату конвертации,
  то есть: 100000 * 0.98 = 98 000.
  Формула вычислений: raw_converted_value = value * rate, converted_value = raw_converted_value * 0.98,
  то есть сначала высчитывается курс, после этого снимается комиссия. Курс -> конвертация -> комиссия -> округление.
- Минимальная сумма для конвертации - 0.01,
- Для криптовалют результат округляется до 10 знаков после запятой,
- Для фиатных валют результат округляется до 2 знаков после запятой,
- ТТЛ последнего закешированного снепшота курсов - 30 секунд, при недоступности сервисов провайдеров - 3600 секунд.

### Аутентификация

Каждый запрос должен содержать заголовок:

```http
Authorization: Bearer <token>
```
При отсутствии или некорректности токена сервис возвращает ошибку `403` c описанием в JSON-формате.

#### Требования к Bearer-токену

Токен является статическим opaque API token: сервис не извлекает из него данные,
а только проверяет его соответствие настроенному секрету.

- Токен содержит ровно 64 ASCII символа из набора `A-Z`, `a-z`, `0-9`, `_` и `-`.
- Формат токена: `[A-Za-z0-9_-]{64}`.
- Токен генерируется оператором/программитом, с помощью генератора случайных чисел
  в Base64 URL-safe без паддинга. Результат имеет длину 64 символа и использует допустимый алфавит.
- Токен передается исключительно в заголовке Authorization. его нельзя передавать в URL, query-параметрах,
  JSON-теле запроса или cookie.

Проверка выполняется в мидлвари:

1. Проверить наличие заголовка `Authorization`.
2. Проверить схему `Bearer` и извлечь значение токена.
3. Проверить длину и формат токена.
4. Выполнить сравнение с секретом из конфигурации.
5. При неуспешной проверке вернуть предусмотренный JSON-ответ с кодом `403`.

Секрет хранится в `.env` вне репозитория для локальной разработки. Токен нельзя записывать в любые логи.

### Поддерживаемые валюты

Сервис поддерживает фиксированный набор валют, определяемый конфигурацией приложения.

В текущей версии поддерживаются:

- фиатные валюты: USD, EUR, GBP, PLN, CZK, SEK, NOK, DKK, CHF, ZAR, AUD, JPY, NZD,
  TRY, BRL, CAD, CNY, HKD, HUF, INR, ILS, MYR, MXN, SGD, RON, PHP,
  ARS, THB, NGN, PKR, AED, UAH, BGN, HRK, RSD, CLP, KRW, EGP, SAR,
  QAR, GHS, MAD, DOP.
- криптовалюты: BTC, LTC, ETH, BCH, XRP, TRX, DOGE, BNB, POL, USDC, SOL, EURC, USDT.

Запрос валюты, отсутствующей в поддерживаемом наборе, завершается ошибкой `422 unsupported_currency`.

## API-контракт

API содержит два метода: `rates` для получения курсов и `convert` для конвертации валют.

### Конвертация

```http
POST /api/v1?method=convert
Content-Type: application/json
```

Тело запроса:

```json
{
  "currency_from": "BTC",
  "currency_to": "USD",
  "value": 1.00
}
```

Поля:

| Поле            | Required | Описание                                        |
|-----------------|----------|-------------------------------------------------|
| `currency_from` | да       | Исходная валюта.                                |
| `currency_to`   | да       | Целевая валюта.                                 |
| `value`         | да       | Сумма для конвертации; значение не меньше 0.01. |

Проверки:

- обе валюты поддерживаются,
- value является положительным десятичным числом,
- сумма не меньше минимально допустимой,
- валютная пара может быть рассчитана,
- применены единые правила комиссии и округления.

Успешный ответ:

```json
{
  "status": "success",
  "code": 200,
  "fetched_at": "<timestamp>",
  "data": {
    "currency_from": "BTC",
    "currency_to": "USD",
    "value": 1.00,
    "converted_value": 1.00,
    "rate": 1.00
  }
}
```

### Получение курсов

```http
GET /api/v1?method=rates
GET /api/v1?method=rates&currency=USD,EUR,EUR
```

Параметры:

| Параметр | Required | Описание |
| --- |----------| --- |
| `method` | да       | Должен быть равен rates. |
| `currency` | нет      | Список кодов валют через запятую. При отсутствии возвращаются все доступные курсы. |

Ожидаемое поведение:

- получить актуальные курсы;
- отфильтровать курсы, если передан currency;
- отсортировать результат по возрастанию курса;
- вернуть ошибку при запросе неподдерживаемой валюты.

Метод rates возвращает курс без применения комиссии.
Комиссия 2% применяется только методом `convert`.

Успешный ответ:

```json
{
  "status": "success",
  "code": 200,
  "fetched_at": "<timestamp>",
  "data": {
    "USD": <rate>,
    "RUB": <rate>,
    "EUR": <rate>
  }
}
```

### Ошибки

Все ответы, включая ошибки, должны иметь формат JSON.

Базовая форма:

```json
{
  "status": "error",
  "code": "<error_code>",
  "message": "Invalid value"
}
```

| Сценарий | HTTP-статус | Код ошибки |
| --- |-------------| --- |
| Токен отсутствует или неверен | `403`       | `invalid_token` |
| Некорректный метод или параметры | `400`       | `invalid_request` |
| Валюта/пара не поддерживается | `422`       | `unsupported_currency` |
| Лимит запросов превышен | `429`       | `rate_limit_exceeded` |
| Источники курсов недоступны | `503`       | `rates_unavailable` |

## Нефункциональные требования

- Время ожидания внешнего HTTP-запроса: 3 секунды.
- Курсы кешируются на срок: 30 секунд для свежих снепшотов.
  Если свежий snapshot отсутствует и оба провайдера недоступны - 3600 секунд.
- В логах фиксируются ошибки источников, переключение на резервный источник и технический идентификатор запроса;
  токены и другие секреты не логируются.
- Расчеты денежных значений выполняются не с помощью float, а с помощью decimal arithmetic.

список ошибок, которые считаем "недоступностью" провайдера:
- connection timeout
- HTTP timeout
- HTTP 5xx
- HTTP 429
- невозможность декодировать корректный response
- response не соответствует ожидаемой структуре

## Тест-кейсы

### Позитивные

- `GET rates` с корректным токеном возвращает полный список курсов.
- `GET rates` с фильтром возвращает только запрошенные валюты.
- `POST convert` корректно рассчитывает конвертацию в обоих направлениях.
- Комиссия и округление соответствуют согласованным правилам.

### Негативные

- отсутствующий, пустой и неверный Bearer-токен;
- неизвестный `method`, неподдерживаемая валюта;
- `value < 0.01`, нечисловое и отрицательное значение;
- невалидный JSON и неподходящий `Content-Type`;
- timeout, `429`, `5xx` и некорректный ответ основного источника;
- успешное переключение на резервный источник;
- недоступность обоих источников;
